# AI同士の相談の仕組み（設計）

- 依頼：`inbox/2026-11-22_026_consultation-system-first.md`
- 状態：段階1（ローカル）を作成。未実行の項目は下の「段階」表を参照

## 1. 目的

- エラーや詰まりが起きたとき、大事な設計を決めるとき、AIが単独で判断せず、他のAIに相談してから進める。
- 相談で作業を止めない。相談の返事が来なければ、期限後に単独で進める。

## 2. 決まり

1. **相談するかどうかは、各AI自身が判断する。** 親方の指示は不要。
2. **相談は止まる理由にしない。** 期限（既定**30分**）を過ぎて返事がなければ、単独で進めてよい。
3. 相談の内容と結果は、報告書（`reports/`）に残す。単独で進めた場合は、その判断も書く。
4. 相手のAIに届かない場合は、その旨を正直に報告する。届く相手だけで進める。
5. **外部への送信は要承認。** Codex・ChatGPTへ質問文を送る操作は、承認があるまで行わない。

## 4. 使い方（段階1）

```powershell
# 相談を作る（IDが表示される）
.\worker\Consult.ps1 -Action New -Topic "件名" -Question "質問文" -TimeoutMinutes 30

# 返信を書く（相手のAIの返答を記録する）
.\worker\Consult.ps1 -Action Reply -Id <相談ID> -From "Codex" -Text "返信内容"

# 状態を見る：waiting / replied / timeout
.\worker\Consult.ps1 -Action Status -Id <相談ID>
```

- `timeout` の時だけ、単独で進めてよい。`waiting` の時は、期限まで待つか、別の作業を進める。
- 保存の形（依頼095で変更）：
  - 質問：`consult/open/<相談ID>/question.json`（件名・期限・質問文。1件）
  - 返信：`consult/open/<相談ID>/replies/*.json`（1返信1ファイル。送信者 `from` と本文 `text` を別の値として保存）
- 返信の本文は値として保存し、文中の書式では判定しない。質問文に返信形式の行があっても返信と誤判定しない。
- 送信者は、保存時に渡された `-From` の値を記録する。本文の自己申告では変わらない。
- 旧形式（`consult/open/<相談ID>.md`）は読めない。既存の相談は0件のため移行は不要（報告書：`reports/2026-11-25_095_agmsgの相談の仕組みの欠陥直し_Claude報告書.md`）。
