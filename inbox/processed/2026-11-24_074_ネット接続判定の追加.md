# 依頼074：両ワーカーへのネット接続判定の追加

- 作成：2026-11-24（モコ）
- 背景：PCがネット未接続の間もワーカーが起動し、失敗を繰り返していた。起動直後に接続を判定し、切れている回は静かに終わらせたい（親方の発案）。

## やること

対象スクリプト2本：
- `worker/Invoke-ClaudeWorker.ps1`
- `worker/Invoke-CodexWorker.ps1`

1. 各スクリプトの冒頭（git pull や本体処理の前）に、ネット接続の判定を入れる。
   - 判定方法の例：`https://github.com` への短いリクエスト（タイムアウト5秒程度）。実際の到達先で判定する方が誤判定が少ないので、git のリモート到達性など、より確実な方法があればそちらでよい。
   - 切れていると判定したら、ログに「オフラインのためスキップ」と1行だけ残し、終了コード0で終了する（失敗扱いにしない）。
2. つながっている場合の動作は今までと変えない。
3. 確認：判定部分だけを切り出して、つながっている状態で「接続あり」と判定されることを確認する。可能なら、ネットを切った状態でも確認する。
4. 結果を報告書に書く（入れた判定方法／確認結果／注意点）。

## 範囲

- 判定の追加のみ。実行間隔やタスクスケジューラの設定は変えない（それは別途判断する）。
- スクリプトの他の動作は変更しない。

## 結果

- 完了（作業ツリーの変更のみ。コミット・push は未実施）
- 変更ファイル：`worker/Invoke-ClaudeWorker.ps1`、`worker/Invoke-CodexWorker.ps1`
  - 判定用の関数 `Test-Online` を追加。既存の処理は変更していない（追加のみ36行）
- 判定方法：`github.com` の443番ポートへTCP接続（タイムアウト5秒）
  - HTTPリクエストは送らず、データも送らない
  - 同じ宛先に `git pull` / `git push` を行うため、到達性の判定として妥当
- 配置：
  - Claude版：ログ開始の直後、`git pull` より前
  - Codex版：ロック取得・git操作より前
- 切れている時：ログに「オフラインのためスキップ」を1行残し、終了コード0で終了（失敗扱いにしない）
- つながっている時：判定後は従来どおりの処理を行う

### 確認結果

- 構文チェック：両スクリプトとも解析エラー0件
- `github.com:443` → 接続あり（True、約970ms）
- 存在しないホスト（`nonexistent.invalid`）→ False（約390ms）
- 閉じたポート（`127.0.0.1:9`）→ False（約2秒）
- 実際にネットを切った状態での確認は未実施（PCの通信を切る操作は行わない方針）。切断時の判定は「存在しないホスト」の結果で代替した
- 確認は Windows PowerShell 5.1（タスクスケジューラと同じ `powershell.exe`）で実施

### 注意点

- 判定が False になるのは接続に失敗した時だけ。`github.com` 側の障害でもその回はスキップされ、次回（30分後）に再試行される
- 実行間隔・タスクスケジューラの設定は変更していない
- 依頼ファイルは `inbox/` に残したまま（`processed/` への移動は未実施）
- 作業ツリーには他の未コミット変更が多数あるため、コミットは行っていない。必要なら本人の判断で、上記2ファイルだけをコミットする
