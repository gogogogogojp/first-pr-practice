## 2. 実装した内容（両方のワーカー）

- 変更ファイル：`worker/Invoke-CodexWorker.ps1`、`worker/Invoke-CodexWorker2.ps1`
- 「完了しなかった」の扱い：Codexを呼んだ後に、報告が空・statusが不正・出力が読めない・実行失敗・外部連携ツールの検出が起きた場合。
- 連続失敗が**3回**に達したら、Codexを呼ばなくなります。
  - `reports/<依頼名>_Codex保留報告書.md` を作ります。
  - 報告書だけを commit して push します（依頼ファイルは inbox に残します）。

- 回数の保存先：`logs/codex-worker-fail.json`、`logs/codex-worker2-fail.json`（logs はGit対象外）。
- **再開方法**：保存先の該当の依頼名を消し、中身を `{}` にします。

### 7-1. 未接続の時間帯の記録

### 7-2. 再接続後の増え方

- 呼び出しは、オンラインの実行ごとに依頼を1件ずつ送る形です。
- 1回の実行で2件送ったのは、CodexWorker の 11/25 21:44 の1回だけです（依頼001の完了の後に003を送った）。

- 11/25 17:34〜19:04 は、10分おきに1回ずつ呼ばれています。まとめて呼ばれてはいません。
- 11/25 16:04〜17:24 は、実行の記録そのものがありません。未接続の記録ではないため、PCが動いていなかった可能性があります（原因は未確認）。
- **訂正**：1節の「11/25 12:14〜19:04の14回は、10分おきの再送です」は不正確です。14回の呼び出しは、途中に未接続や実行の無い時間をはさんでいます。

- 判定の中身（両方とも同じ）：github.com の443番ポートへ5秒以内に接続できるかを見ます。データは送りません。
- 順番：判定 → 未接続なら終了（Codexを呼ばない）→ 接続できていれば依頼の処理。
- 追加された時期：CodexWorker は 11/24 の commit `526c8e8`、CodexWorker2 は 11/24 の commit `e3f523d`（「CodexWorker2の追加」）です。
