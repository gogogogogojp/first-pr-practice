# 依頼004 報告書：Codexタスク登録の確認（ハチ）

## 結論

**タスクスケジューラの登録有無は確認できませんでした。**
理由は、スケジューラを調べるコマンドが実行許可で止められたためです。
登録が無いという事実は、まだ確認できていません。

## 実施事項

1. 依頼ファイルと作業ルールを読みました。
2. タスクスケジューラへの問い合わせを、方法を変えて複数回（6回）試しました。対象は `CodexWorker`、`CodexWorker2`、`ClaudeWorker2` と、全体一覧です。
   - 試した方法：`schtasks /query`（個別と全体、詳細表示あり・なし）、PowerShellの `Get-ScheduledTask`。
   - 結果：すべて「承認が必要」「実行できない」と返され、中身は取得できませんでした。
3. 代わりに、リポジトリ内の資料を確認しました。ただし、これは**設定された予定**であり、**現在の登録状態ではありません**。

## リポジトリ内の資料（確認できた事実）

| タスク名 | 資料に書かれた予定の起動時刻 | 資料の出どころ |
|---|---|---|
| CodexWorker（オウル） | 毎時14分・44分 | `inbox-codex/README.md`、`docs/UNIT2-PLAN.md` |
| CodexWorker2 | 毎時04分・34分 | `inbox-codex2/README.md` |
| ClaudeWorker2（ハチ） | 毎時09分・39分 | `inbox-claude2/README.md` |

- 過去の依頼（083）では、CodexWorker と CodexWorker2 が **2026-11-24 夜に実行されていた記録**があります（処理済み依頼の記述）。
- そのため「一度も登録されていなかった」とは断定できません。登録が消えた可能性と、登録はあるが動いていない可能性の両方が残ります。

## 未確認の項目（要確認）

- 3つのタスクの登録有無
- 前回の実行時刻・終了コード
- 次回の実行時刻
- 状態（有効・無効）

## 直しの案（実施していません）

1. 親方が、以下のコマンドをPCで1回実行し、結果を貼る。
   - `schtasks /query /fo LIST /v` を実行し、「CodexWorker」「CodexWorker2」「ClaudeWorker2」の部分を見る。
   - 成功の判断：3つの名前が出て、「次回の実行時刻」が未来の日時であること。
2. 登録が無い場合は、既存の登録手順（inbox の README 記載の設定）で再登録する。再登録は実機の変更なので、親方の確認を取ってから行う。
3. 有効でも実行結果が失敗なら、前回の終了コードを基に原因を切り分ける（依頼002・003の続き）。
